# Standalone Pyramid Task 4.2.1

This maintenance release reorganizes the runtime and improves agent entry
guidance. The complete plugin remains Python 3.10+, with matching Codex and
Claude manifests, 17 skills and 26 CLI commands. Project format V3, plan/state
schemas, canonical authority and evidence requirements remain compatible.

## Runtime and agent entry

Pure rules, storage/publication, task/plan commands, queries, CLI adapters,
history, assurance and observer values have explicit owners. The core facade
preserves public exports, signatures and named clock/fault adapters. The viewer
loads package-relative HTML/live resources; copy the complete plugin, including
all sibling modules and assets. See [runtime navigation](../runtime-navigation.md).

Skill names, UI prompts and task-packet contracts remain unchanged. Four discovery
descriptions have clearer operation routing. The task entry retains helper
capabilities and selection criteria; authorization, capacity and expected benefit
are checked before the relevant collaboration contract is read and a helper is
chosen. Valid packet/evidence reuse and narrow audit queries avoid unnecessary
reading without waiving source freshness, dependencies or required inspections.

The stdlib metadata/resource validator and trace-grader regression tests run with
ordinary repository checks and CI. The optional [decision evaluation runner](../../tools/skill_evals/README.md)
uses separately authorized, read-only Claude sessions; ordinary checks call no
external model service. Historical stage runners and full experimental traces
remain local development evidence and are not installation dependencies.

## Compatibility and verification

The completed source refactor retained the original 163 public exports/signatures
and assigned all 125 original core functions to explicit implementations. Its
qualification used independent frozen-source comparisons, real competing
processes, injected write/process faults, graph-last publication and proof-blob
checks, complete copied-plugin execution, and ten inspected browser captures.
The earlier 204-test suite was retained; the current runtime suite has 235 tests.
Stage proof remains historical evidence, not a new installed-host certification.

Release preparation validates the exact selected source copy, both manifests and
runtime version, 235 runtime tests, 17 maintenance tests and a real CLI journey
from a different working directory. The selected Git tree is checked again before
publication. The release archive is generated from the release tag and published
with SHA-256 checksums. CI results for the released commit are linked in its GitHub
Release; local and CI optional ast-grep results are reported separately.

## Measured context changes

Against the original 4.2.0 source, core decreases from 5,999 to 613 physical lines
(89.8%). At the completed refactor baseline, runtime Python plus relocated resources totaled 14,987 lines, about 10.7%
more than the original runtime: boundaries and compatibility wrappers add code.

The twelve predefined static import-closure cases include full dependencies.
Five local-rule cases average 10,061 to 2,772 lines (72.45% less); seven cross-layer
cases average 7,715.7 to 7,270.6 (5.77% less). Pause/resume and other complete core
transactions increase to 11,422 lines (13.53% more). C02/C04/C05 still miss their
declared local budgets; the split does not make every transaction a local read.
These are static source measurements, not observed agent context use or tokens.

For the six edited skills, discovery descriptions total 2,289 to 1,428 characters;
complete entry text totals 36,209 to 36,297. The take entry is 5,621 to 5,170
characters. Entry decision information is retained; total instruction text is
approximately unchanged.

## Evaluation and remaining limits

Three synthetic read-only decision scenarios were run once per version, in six
fresh built-in agent contexts. Separate cross-review, reusing evaluator contexts, accepted old and new answers
in 3/3 scenarios each, with no observed gain or regression. The comparison was
between the preceding lean guidance and the latest helper/navigation additions,
not original 4.2.0 versus the complete refactor. Both helper cases entered through
orchestrate, so the new take summary's individual effect was not isolated.

The original literal answer-key result was 0/6 complete matches. Its no-helper
aliases and accepted helper routes were incomplete; future v2 fixtures and two
regression tests correct those definitions. Historical scores were not rewritten.
Native installed-host discovery, actual helper execution, model tokens and general
workflow speedup remain unqualified. The external Claude evaluation was not
completed and is not counted as a quality sample.

Dependency analysis keeps the Python default and optional ast-grep adapter. The
frozen Rust re-export pilot still has 2 TP / 0 FP / 2 FN (50% file-edge recall).
The pre-existing schema-2 clean failure on a proof-artifacts directory and narrow
graph horizontal scrolling were preserved by the compatibility refactor.

The local refactor chronicle's exact Git binding remains pending: its full stage
evidence and the later guidance/release changes do not form the same exact file
set. This release establishes source identity through its Git commit, tag and
archive, without claiming artifact-identical canonical replay. Publication does
not update installed plugins, migrate plans or deploy a service.
