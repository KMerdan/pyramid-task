# Decision and measurement contract

Established before implementation, 2026-10-05. Applies only to this improvement
intent. Canonical task contracts own acceptance; this document owns comparisons.

## Cases and reproducibility

Use `measure_baseline.py` with the shared Python interpreter, an exact installed
plugin or frozen candidate path, a fresh owned output directory, and the preserved
4.1 archive path. It creates working, blocked, missing-visual, stale-proof and
branched disposable cases through runtime interfaces. Staleness follows an actual
successful identity subprocess and audit, then a changed input. That success
proves fixture identity, not a product or model review. The completed case uses
the prior archived display; its historical green is not current worktree proof.

Capture selected node/harness/readiness/ready/summary/assurance queries three
times per case, plus actual rendered snapshots. Do not change cases or fields
between baseline and candidate runs. Preserve failure outputs. Developer calls
disable usage collection; canonical dogfood calls retain normal accounting.

## Comparison budgets and decision-critical information

Before code changes, set these relative bounds:

- Selected node, harness and assurance record responses: target at least 30%
  fewer bytes where redundant detail exists. Never truncate load-bearing detail
  to meet this target; explain a missed target and retain explicit full recovery.
- Selected queries should not construct an unused full graph. Prove with call
  instrumentation/regression tests, not a timing-only inference.
- Median CLI latency: no unexplained increase above 20% on matched cases;
  repeat noisy cases and report spread. No timing claim from a single sample.
- Observer proof summaries: bounded observations and claim-linked references,
  no raw logs, credentials or embedded unlimited images. Explicit omissions
  must offer a supported way to recover the original evidence.
- Goal prompt: normally 250–600 words, shorter when scope permits; add only
  applicable boundaries. Word count is a guideline, not a safety-field limiter.

Always retain target/authority identity, lifecycle, execution, verification,
health, availability, ownership, relevant dependencies, blockers, valid mutation
guards, required acceptance/proof boundaries and exact recovery pointers.
Harness capture must retain executable input identity and required channels;
summary-only display must not pretend it is a submit-ready run template.
Assurance selectors must identify coverage and related blockers, never invent
readiness or suppress unresolved drift/findings. Reject malformed selectors.
Full results and historical evidence remain accessible. Take/resume retain the
complete task contract unless an explicit user-selected narrower read is made.

Report stdout bytes, subprocess duration, repeated internal work, native usage
and human comprehension separately. Byte reductions are not token savings.
The earlier native pilot did not establish savings. Any prompt-only comparison
uses the same runtime, cases and permissions; unrun native/provider evaluations
remain unverified. Semantic decision review is not independent human research.

## Engineer questions and visual grammar

At desktop and narrow widths, the Observer must answer:

1. What outcome has recorded acceptance, and what is not currently verified?
2. Who owns active work, what can proceed, and what needs a decision?
3. What specifically prevents the next acceptance boundary?
4. What evidence supports this exact claim, including required visual proof?
5. Is this publication connected/current, or merely the last valid snapshot?

Recorded verification, current proof eligibility and connection/publication
health are separate facts. Default observation is recorded-candidate; it must
not perform an expensive hidden working-tree scan or imply current eligibility.
Use consistent labels, hierarchy and progressive disclosure; never color alone.
Do not draw arrows between independent outcomes. Keep detail ahead of a long
tree on narrow displays. Reuse Playwright, capture real pages, inspect images,
and check keyboard, 320/375/1280 widths, 200% zoom, light/dark/reduced motion,
live selection and preservation of the last valid publication. DOM assertions
and screenshots exist separately from actual visual judgment.

## Asset and inspection contract

Retain the six existing asset IDs/history. Add narrow ASSET-OBSERVER (visualizer
and live publication), ASSET-OUTPUT (compact projection) and ASSET-IMPROVEMENT
(this planning/measurement area). Extend packaging only with missing context,
host guidance and documentation index. Overlapping schema/test areas remain
explicit; do not create a root-wide asset to suppress drift.

Map each work node to its actual source assets using `assess`/`impact`. Inspection
records remain planned until execution establishes their claims. Refresh only
the task/asset inspections consumed by its audit after the implementation event;
reuse task or gate evidence instead of rerunning a test to fill a record. Broader
integration inspection occurs at TASK-551/final gates. Gates inherit provider
scope through dependency closure; affected producer proof must still match.
Rollback is preserved-main/candidate Git recovery plus supported canonical
archives, not destructive checkout reset. Development monitoring uses current
readiness, tests, browser findings and the artifact inventory; no deployment.
